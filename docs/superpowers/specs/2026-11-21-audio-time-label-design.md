# 音频到达时刻字段的可读性修正

## 意图

用户把「最近收到音频 11:51:54」读成了「11 小时 51 分 54 秒」，误以为服务已经十多个小时没收到音频。
原因是该字段是**时刻**，但标签没说明，且与旁边同为「冒号分隔三段数字」的**时长**字段视觉上无法区分。

## 目标

- 不改语义、不改数据来源：仍然是 `/api/monitor` 的 `last_audio_at`（UTC，界面转北京时间）。
- 让「时刻」和「时长」在眼睛扫过时就能区分。

非目标：不调整轮询频率、不改 API 字段、不改归档区的时间显示。

## 方案

标签改为「最近音频到达时刻」，数值后追加小字「北京时间」。
时长字段（`采集时长`）永远不会有这种后缀，因此两者不会再混淆。

已否决的替代方案：

- 只把标签改成「最近音频到达时间」：改动最小，但 `11:51:54` 仍容易被读成时长。
- 「最后收到音频 于 11:51:54」：中文更口语，但没说清时区，且「于」夹在数值前不易扫读。

## 改动范围

- `static/index.html`：「直播间守卫」「本机录音」两个卡片的标签与占位结构。
- `static/app.js`：把 `textContent` 赋值改为「文本 + 小字」，避免覆盖后缀；本机录音状态文案改为「最近到达」。
- `static/style.css`：给后缀小字加左间距。
- `tests/test_static.py`：断言新标签存在、旧标签消失、两个字段都渲染「北京时间」后缀。

## 留给实现者

- 只有存在真实时间时才显示「北京时间」后缀，占位符 `—` 时不显示。
- 保持现有的 `title` 悬浮提示（含日期）不变。
