# ValuSense 档案交互与分析队列开发计划

## 目标与已确认的决定

在现有直播守卫、本地人物判断和普通话转写上，增加整场与单片分析入口、档案折叠、时间排序和分析队列。保留监听、手动快照、实时补分析及断点恢复。

单片重新分析采用用户确认的**独立复核**：不覆盖整场综合文本，不改变整场人物编号。单片人物编号只在该切片的该复核版本内有效。

## 页面与操作

- 左上角菜单图标打开宽约 260px 的左侧悬浮抽屉，内部为“ValuSense”和“分析队列”，使用 `#/home`、`#/queue`；默认收起，不保留侧边栏占位。菜单覆盖页面，背景轻微变暗，再次点击图标、点击背景、按 Esc 或选择入口均向左收起。支持键盘导航、刷新与前进后退；页面切换不停止后台采集、分析或播放器。
- 历史场次默认折叠，点击在该场次下方展开，再次点击折叠全部内部内容；允许同时展开多个场次。
- 场次内容包括信息、分析进度、缺口、整场分析按钮、综合记录及按序切片列表。综合记录独立折叠。
- 每个“第 N 段”可以独立展开，显示接收时间、人物、文字、重叠/待确认标记及回听。跨切片发言在相关切片中标记“跨段发言”，整场记录中只出现一次。
- 每 2 秒刷新；按稳定 ID 更新，保留展开、滚动和播放器状态。重新加载浏览器默认折叠。
- “分析当前场次全部切片”操作守卫的当前场次，未有当前场次时禁用；历史场次内提供“分析本场全部切片”和失败后的“重试未完成分析”。
- 每个切片提供“分析”和“重新分析”，显示整场记录与单片复核两种结果。默认优先整场结果，否则显示单片复核。
- 手动请求只包含点击时保存完成的 WAV；正在写入的尾段等待下一次请求。实时开关补分析已有音频并持续处理新增音频。

## 分析队列

- 按分析请求显示记录与进度条；整场提交对应一条记录，重复点击复用已有请求。完成记录保留，单片复核独立展示。以已完成切片数/本次请求总切片数计算进度，等待末尾发言整理时最高 99%；展开记录查看其切片状态，记录与切片各自分页，每页 50 条。正在执行的请求优先显示，等待记录按单片优先及提交顺序排列，完成记录按最近提交时间排列。
- 当前任务显示场次、切片序号、分段 ID、时间范围、任务类型和耗时；空闲显示当前无任务。
- 队列概览显示“排队中：N 个切片任务”；每条分析记录展开后显示其已完成、正在执行和等待中的切片，分页默认 50 条、上限 100。
- 数量包含已请求但尚未生成窗口任务的切片，不包含正在执行、成功或失败待处理的任务。尾段收尾任务明确标记。
- 等待模型、等待上下文、失败待处理在对应记录中显示原因；失败可重试。
- 点击任务跳回主页并展开对应场次与切片，支持不在当前档案页的历史切片。
- 当前窗口结束后优先手动单片任务；相同类型按请求先后执行，整场内部按切片顺序。仅一个模型工作进程，不增加暂停、取消或拖动排序。

## 数据与接口

- 复用现有分析服务、人物/转写适配器及持久队列；分析范围区分 `session` 和 `segment`。
- 整场维持跨 WAV 合并、共享人物档案和顺序推进。单片可读取同连接的前后段上下文，但只提交中心切片，完成时结束待定发言。
- 单片复核创建独立版本。新版本等待或失败时仍可查看旧成功结果；成功后切换。重复点击复用未完成请求。
- 整场查询只读取整场范围，避免单片覆盖。SQLite 升级前用 backup API 备份；增加范围、切片、版本和发言来源索引，保留旧记录与任务。
- 所有文本按 `(start_at, end_at, id)` 排序，时间为音频接收时间。数据库 UTC，界面及可读导出北京时间。缺口穿插在对应位置。
- 增量读取仍按写入 ordinal 选择批次，`next_cursor` 取批次最大 ordinal；显示按时间插入，避免排序导致漏读。TXT、MD、JSONL 原子重建并采用一致时间顺序。

| 接口 | 功能 |
| --- | --- |
| `POST /api/segments/{id}/analysis` | 请求单片复核；`reanalyse` 创建新版本，`retry` 重试失败请求 |
| `GET /api/segments/{id}/analysis` | 最新请求及当前可用成功版本 |
| `GET /api/segments/{id}/utterances` | 按 `scope=session/segment` 读取整场来源记录或独立复核 |
| `GET /api/segments/{id}/transcript` | 下载独立复核 TXT、MD、JSONL |
| `GET /api/analysis/queue` | 当前任务、准确等待数量、分页列表和失败任务 |
| `GET /api/analysis/requests` | 分析请求记录及各自进度，包含已完成记录 |
| `GET /api/analysis/requests/{run_id}/segments` | 按本次分析范围读取切片状态，支持分页 |

切片列表附带分析状态摘要，避免逐条请求状态。不存在返回 404，尚未完成切片分析请求返回 409；沿用本机来源验证。

## 开发顺序与验收

1. 数据迁移、范围和版本、来源索引、单片任务。
2. 单片 API、状态摘要、队列计数和分页。
3. 整场/单片按钮、场次和切片展开。
4. 时间排序、增量游标与导出。
5. 导航、队列跳转、文档和浏览器验证。

自动化覆盖独立范围、幂等、复核版本、故障恢复、跨段来源、排序游标、队列数量/分页/优先级和旧数据库迁移。浏览器验证多个场次/切片开合、刷新保留、路由返回、队列跳转和播放不被刷新打断。执行 pytest、Ruff、Python 编译和 JavaScript 语法检查。

使用已有真实直播音频验证整场、单片和重新分析；短时并行采集验证守卫不受分析影响。报告区分模拟适配器与真实模型结果，不把模型可运行等同于准确率达标。

## 默认值与边界

继续使用 Community-1、Paraformer-zh 和 CT-Punc；不升级依赖、不增加框架。综合记录和整场人物编号按场次隔离。保持默认手动和实时补分析行为，音频完整保留。不增加云服务、账号身份判断、逐人声源分离或删除功能。
