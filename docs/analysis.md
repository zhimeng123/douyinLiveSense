# 识别与分析

默认是**仅录音**。只有识别方式选为“纯本地模型识别”且模型就绪后，实时分析、整场分析和单片复核按钮才会启用。

## 三种识别方式

登录后打开菜单“网站配置 → 识别方式配置”：

| 方式 | 行为 |
| --- | --- |
| 仅录音（默认） | 只保存音频，不分析 |
| 纯本地模型识别 | 本地转写与人物判断，需要先准备模型 |
| 飞书秒记 | 尚未支持，接口返回 409，选项不可选 |

任务进行中（直播间守卫或本机录音）无法更改识别方式，需要先停止任务。接口层对应 `GET/PUT /api/preferences` 的 `mode` 字段。

## 模型与下载

| 用途 | 模型 | SDK |
| --- | --- | --- |
| 讲话区间、窗口内人物判断、声纹向量 | `pyannote/speaker-diarization-community-1` | pyannote.audio 4.0.7 |
| 中文普通话转写 | `funasr/paraformer-zh` | FunASR 1.4.16 |
| 中文标点 | `funasr/ct-punc` | FunASR 1.4.16 |

- Community-1 需要 Hugging Face 只读 Token，并在[模型页面](https://huggingface.co/pyannote/speaker-diarization-community-1)接受条款。
- 网页里保存的 Token 存到服务端 `data/models/hf_token`，API 与日志不返回明文；`HF_TOKEN` 环境变量只是兼容回退。
- 在“网站配置 → 识别方式配置”点“下载缺失模型”，页面每秒显示后台进度。下载失败会保留已完成文件，刷新页面或重启服务后可继续。
- 命令行等价方式：`./scripts/run.sh prepare-models`；只要转写与标点时加 `--asr-only`。
- 实际 revision 与文件 SHA256 记录在 `data/models/manifest.json`。磁盘约预留 **15 GB**，长期录音还需要额外音频空间。
- 关闭识别方式**不会**删除已下载模型，随时可以重新开启。

模型在独立子进程中加载并复用，分析任务串行执行。首次加载和积压会增加等待时间。人物判断自动选择可用的 CUDA、Apple MPS 或 CPU；指定不可用设备会显示错误。普通话与标点模型使用 CPU。

## 整场、实时与单片复核

- **整场分析**：在音频档案展开场次，点“分析本场全部切片”；正在监听的场次用卡片底部的“补齐未分析切片”。
  - 已结束场次请求全部已保存切片，包括不足切片时长的尾段。
  - 正在采集的场次只请求点击时已保存完成的 WAV；正在写入的切片等后续请求。
  - 同一配置下重复点击会复用已有请求，只补分析新增切片，已成功内容不重复生成。
- **实时分析**：卡片底部“实时分析”开关。开启后先处理本场此前未分析的音频，再持续处理新切片；运行中开启也会补分析。关闭后已请求内容继续处理，后续切片等待手动请求。
- **单片复核**：在“第 N 段”内点“分析”创建复核，点“重新分析”创建新版本。可以切换查看“整场记录”和“单片复核”。
  - 复核使用相邻音频作为上下文，只保存中心切片的结果。
  - 独立于整场分析，不覆盖整场文字和人物编号，也不自动并入整场综合记录。
  - 连续点击未完成的请求会复用；新版本等待或失败时仍可查看上一次成功结果。

这是按音频切片和相邻上下文处理的记录，通常在切片保存后才生成文字，不保证逐字即时字幕。模型未就绪时保留分析请求并提示原因，录音采集继续。服务重启会恢复守卫、实时开关与未完成任务；下一次手动开启守卫默认关闭实时分析。

## 分析队列与进度

左上角菜单图标展开悬浮菜单，包含 **ValuSense** 主页和**分析队列**（`#/home`、`#/queue`），支持浏览器前进后退。

- 一个整场请求对应一条记录；单片复核的每个版本各有记录；完成记录保留。
- 每条记录显示进度条、已完成/总切片数、音频时长和正在处理的切片；展开可查看切片状态、编号和 ID，点击切片跳回对应档案。
- 记录与切片列表每页 50 条，上限 100。
- 进度按**已成功提交结果的切片数**计算，正在处理的切片不会提前计入；等待末尾发言收尾时最高 99%，完成或实时分析追上时 100%。实时采集产生新切片后总数增加，进度可能回落。
- 模型缺失、等待上下文和失败会显示具体原因；失败可“重试未完成分析”。
- 调度在当前窗口完成后优先处理手动单片复核，同类型按请求先后执行，整场内部按切片顺序处理。

## 人物编号

| 场景 | 是否复用人物记忆 |
| --- | --- |
| 同一整场分析中的不同切片 | 是，持续匹配已保存的声纹向量 |
| 同一分析中断线重连、补分析或服务重启 | 是，人物档案保存在 SQLite |
| 不同直播场次 | 否，各场次独立 |
| 单片复核及其不同版本 | 否，每次复核版本独立 |
| 更换模型配置创建的新分析版本 | 否，使用对应版本的人物档案 |

没有跨场次的全局人物声纹库。人物编号代表音色聚类，不等于姓名或抖音账号；不同场次的“人物 1”不能直接认作同一个人。样本过短或匹配不明确时显示“人物待确认”。

同时讲话会标记“重叠讲话”，文字来自混合音频。当前没有逐人声源分离，也没有通过抖音连麦事件确认身份。可以点“回听发言”复核原音，包括跨 WAV 的同一次发言。

## 文本与下载范围

- “整场综合文本记录”汇总本场当前整场分析的发言，按音频接收时间排列；跨切片的同一次发言只记一次。
- 网页分批读取，初次最多 100 条，之后可“加载更多发言”。
- **整场下载包含该整场分析已生成的全部发言**，范围不受网页已加载条数限制；TXT、Markdown、JSONL 都从数据库完整读取并按时间排序。
- 仍未分析、失败或尚待收尾的内容不会出现在下载中。要获得完整记录，应先停止采集、请求全部已保存切片并等待分析完成。
- 单片复核结果单独下载，不自动并入整场记录。

SQLite 是记录的来源；文档随分析更新，每次从数据库原子重建。异常退出后可恢复待更新文档，导出失败不会丢失数据库中的结果。TXT 与 Markdown 包含采集缺口；JSONL 每行保存一条发言、源切片采样范围和模型配置，缺口由场次事件接口读取。
